Console SaaS (BlueXP) runtime client setup.

1. OpenAPI schema:
   Copy tools/console_openapi/generated/console_openapi.yaml from the repo into
   this directory:

       cp tools/console_openapi/generated/console_openapi.yaml \
          ~/.config/pynetappfoundry/apis/console/

   The runtime client (ConsoleAPIClient) loads the spec from
   config.get_schema_location("console") / "console_openapi.yaml".

2. Auth (at least one of user_token, service_token or client credentials):

   user_token (optional if a service account is configured):
   - Log into BlueXP at https://console.bluexp.netapp.com
   - Open browser devtools -> Application -> Local Storage / Cookies
   - Copy the JWT-shaped Bearer access token used in Authorization headers
   - Paste into consoleapi.toml [general].user_token

   service account (client credentials, recommended for unattended use):
   - Create a service account in the Console and note its client ID and
     client secret
   - Put them in consoleapi.toml [general] as client_id and client_secret
   - The client exchanges them for a service token (OAuth client-credentials
     grant) when it is constructed, keeps it in memory and renews it before
     it expires. Do not also set service_token.

   service_token (optional static alternative, for service-typed endpoints):
   - Obtain a service token with a client-credentials exchange for the
     service account (the same grant the client performs)
   - Paste the access JWT into consoleapi.toml [general].service_token
   - It is not renewed; it must be replaced when it expires.

   The OAuth refresh-token grant for user tokens is out of scope for now.

3. Test it:

       uv run python -c "
       from pynetappfoundry.core.config import Config
       from pynetappfoundry.console import Console

       config = Config(config_dir='~/.config/pynetappfoundry')
       console = Console(config)
       org = console.get_organization()
       print(f'{org.id}: {org.name}')
       "
